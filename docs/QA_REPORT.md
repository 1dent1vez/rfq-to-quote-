## Real workflow exercised

- Manual default and explicit opt-in offline suggestions; original text and source spans retained.
- Strict TXT/CSV filename, size, encoding, binary/control and schema checks; actual CSV multipart upload through Chromium.
- Explicit SKU/quantity review, supplemental actor/reason evidence and unresolved-context classifications.
- Unknown SKU and unsupported/missing vehicle facts block acceptance; source-catalog claim is not fitment certification.
- Incomplete review blocks draft server-side. Unsaved UI changes block draft/approval.
- Decimal subtotal and IVA: two GP-149 at the initial synthetic price yield subtotal 300.00, IVA 48.00, total MXN 348.00.
- Approval binds exact case/evidence, quote version, commercial rules, catalog and inventory snapshot.
- Duplicate intake is idempotent; changed input under the same identifier conflicts. Stale request/inventory versions, changed price, insufficient stock and margin violations reject safely.
- Parallel approvals for two units with only two available produce one successful approval and one rejection. The winning exact approval can be repeated with no extra reservation or inventory audit event.
- Case and operational audit read back exactly after server restart. Approved cases reject review/draft writes; downloads remain read-only snapshots.
- HTML escapes untrusted customer strings; CSV guards spreadsheet formulas. SQL uses parameters, downloads use generated UUID filenames, same-origin mutation and loopback Host restrictions were tested.
- Demo reset requires its exact confirmation, actor/reason and portfolio DB identity; it preserves operational audit and never uses the historical ledgers.

## Issues found and corrected during RED/GREEN and QA

| Finding | Correction / regression evidence |
|---|---|
| Old default frontend entrypoint still displayed historical intake | New `portfolio-main.tsx` and index entry, with actual browser failure then successful integrated flow; original entrypoint preserved |
| Fresh install lacked the historical adapter's `httpx` import | Locked both HTTP client families and dependencies; fresh full suite and `pip check` passed |
| Inventory table stayed stale after successful approval | Refresh on persisted case version change; browser asserts reserved 2 and available 18 |
| Inventory editor silently adopted a newer version after table refresh while keeping older fields | Editor version stays tied to displayed fields; explicit reload/discard action and component regression |
| Identical commercial lines in different requests had the same snapshot | Snapshot now binds exact customer/request/evidence; cross-request approval regression rejects |
| Parser bounds could escape as a server error; control characters could enter text | Fail-closed 422 handling and strict text validation |
| JSON-escaped unpaired Unicode surrogates caused 500 in fingerprints, persistence or validation-error rendering | Shared recursive pre-validation checks strict UTF-8 encodability for intake and all mutation/nested strings before hashing or database work; returns a safe 422 without echoing invalid text. Raw-JSON TestClient RED: **54 failed, 6 passed** before the fix; GREEN: **60 passed** (58 high/low-surrogate rejection cases assert identical persisted SQLite state; 2 accented-Spanish/emoji end-to-end cases preserve valid text). Full backend **315 passed**, frontend **18 passed**, TypeScript/Vite build passed; no running-server restart or inference performed for this correction |
| A 100-line request could have 200 valid unresolved fragments but the review schema allowed only 100 | Bounded review allowance covers those literal fragments, with exact-ID classification checks and regression |
| Substantive context could be called a greeting | `non_substantive` limited to exact versioned-in-code greeting literals; other context needs explicit human resolution |
| Quote export omitted confirmed vehicle context | HTML displays the confirmed source claim and reference-only non-certification scope |

## Scope and limitations

- Linux Python 3.14 and Node 22 were exercised; other platforms/versions were not independently tested. Chromium used Playwright's Ubuntu fallback build on the local Linux host and ran successfully. No tool-approval bypass or system-browser modification was performed.
- Component tests use recorded synthetic fixtures and transport doubles. Real HTTP/Chromium scripts provide separate non-mock proof.
- Demo actor labels are not identity verification or authorization. Reset/inventory endpoints are intentionally local-operator controls; do not expose this service publicly.
- Partial in-progress UI edits are not autosaved. Human semantic resolutions are operator assertions with new evidence/reasons, not model-verified facts.
- SQLite gives local atomic reservations, not external warehouse consistency. Its audit is persistent, not tamper-proof against administrators.
- No real model performance improvement, customer validation, ROI, server-generated PDF/OCR, ERP/email, production deployment, tax certification or hosted CI success is claimed.
